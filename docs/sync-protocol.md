# HITA Watch 同步协议 v1

传输层：华为 Wear Engine 对等消息。两端应用身份在传输层匹配；CRC32 只检测损坏，不承担身份认证或加密职责。应用不自己建立网络后端或裸蓝牙连接。

安卓与原生鸿蒙使用**同一份 v1 协议**，不在课表或消息中添加用于选择身份的 `platform` 字段。平台由手表构建配置决定；原生允许清单和 SDK 对端配置负责应用身份匹配，不信任消息中自行声称的来源。

原生鸿蒙手机通过 `@kit.WearEngine` 的 `P2pMessage.content: Uint8Array` 发送 UTF-8 JSON；手表的轻量级 SDK 回调交付字符串，再交给本接收器。不要给正文额外套 Base64 或改成 UTF-16。鸿蒙身份、接口和后续接入要求见 [鸿蒙互联说明](harmonyos-integration.md)；手机端本次尚未实现。

## 课表快照

```json
{
  "version": 1,
  "timezone": "Asia/Shanghai",
  "generatedAt": 1791166440000,
  "rangeStart": "2026-10-05",
  "rangeEnd": "2026-10-18",
  "timetable": {
    "id": "actual-phone-timetable-id",
    "name": "2026秋季学期",
    "campus": "威海",
    "termStart": "2026-08-31"
  },
  "events": [{
    "id": "actual-phone-event-id",
    "title": "离散数学",
    "room": "N楼-118",
    "teacher": "王老师",
    "sections": "第7-8节",
    "kind": "CLASS",
    "startAt": 1791187500000,
    "endAt": 1791193800000
  }]
}
```

上例是协议演示，不是真实教务数据。时间戳为毫秒，所有日期以 UTC+8 解释，与手机系统临时设置的时区无关。

- `rangeStart`、`rangeEnd` 均包含当日，范围最长35天。
- `termStart` 是第一教学周周一，不能由手表猜测。
- 整个 JSON 最大65536字节 UTF-8，事件最多240条，ID唯一。
- `kind` 为 `CLASS`、`EXAM` 或 `OTHER`。考试忽略节次显示。
- 标题最多100个 UTF-16 单元，教室/教师各120，节次30。
- 必须提供有效起止时间，持续时间大于0且不超过48小时，并完全落在声明覆盖范围中。
- 接收器只保存白名单字段；不传登录信息。手机转换器同样只输出允许字段。
- 快照按当前选择的课表整体替换，不追加，避免删除后同步导致重复课程。

## 消息时序

公共头：

```json
{"p":"hita-watch","v":1,"t":"begin","id":"unique-transfer-id"}
```

`id` 最长64个字符，只允许字母、数字、`_`、`-`。

1. 手机发送 `begin`，附 `total`、UTF-8总字节 `bytes`、8位小写CRC32 `crc`；手表回复 `ack,next:0`。
2. 手机发送 `chunk,n:0,data:"..."`，手表回复下一个期望序号 `ack,next:1`。
3. 每片正文最多384字节，分片不切断 Unicode 代理对。总片数最多256；消息封装后限制2048字节。
4. 一次只发一片，收到确认再继续。普通确认超时6秒，重发最多3次；保存确认等待12秒。
5. 全部片段确认后发送 `end`。手表校验大小/CRC/业务数据，写入缓存并回读验证，才回复 `done`。
6. 安卓 `onSendResult=207`、鸿蒙 `sendMessage()` 的 `P2pResult.code=207` 均只表示底层发送成功，不代表手表已保存。
7. ACK或done丢失时重发相同片段/结束消息。接收端幂等处理，不重复写入课程。
8. 90秒没有有效传输活动则丢弃未完成传输，保留原缓存。同步中退出前台会取消接收中的分片；已经开始的安全保存会完成。
9. 手表可发送 `request` 请求最新快照。手机监听器通知宿主生成真实快照，不在后台偷偷登录教务。

`error` 包含 `SIZE`、`CHUNK`、`CHECKSUM`、`INVALID_DATA`、`STALE`、`STORAGE`、`TIMEOUT` 等原因。保存中收到并发消息回复 `busy`。所有失败在 UI 中都不能显示同步成功。

## 本地保存

使用 liteWearable `@system.storage`，每值最多2000字节，键名不超过32字符。a/b双槽分片保存：

1. 清除非当前槽的描述符；
2. 保存全部分片；
3. 最后写入包含代数、片数、CRC的描述符并完整回读；
4. 成功后切换活动槽。

启动时校验两槽，使用代数最新且完整的一份；最新槽损坏时回退。真实存储读取错误与正常未初始化状态分开，读取失败时拒绝覆盖。导入时间更早的快照被拒绝。
